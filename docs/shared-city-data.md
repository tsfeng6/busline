# 城市线路 JSON 与 GitHub 历史快照

## 当前架构：读取与上传分离

- 查看共享线路、历史索引和下载历史快照：只请求网站同源 `/city-data/v1/...` 静态 JSON，由 GitHub Pages 提供。
- 最新快照、历史索引中列出的快照及所有引用分片，会在网站构建时从 `busline-data` 分支的同一提交复制到 `public/city-data/`，Vite 再将其复制到 `dist/`。
- 旧的大份单文件在静态构建中转换为无损压缩分片，原仓库文件和历史版本不修改。当前发布总预算900MiB，超额会停止部署并保留线上旧版本。
- 读取失败只重试同源文件；404提示未发布/仍在发布中，不再请求 Worker、`workers.dev`、`raw.githubusercontent.com` 或 GitHub REST API。浏览器HTTP缓存可复用未变更的数据，不保证离线首次访问。
- 全市检索在浏览器中进行，完成后由用户确认是否上传。上传仍使用现有网关和 Actions，与静态读取没有调用依赖；EdgeOne 上传迁移完成前保留旧入口。
- 上传网关暂不可达时，已有静态线路仍可查看；本地检索、导出也可使用。
- `VITE_CITY_DATA_READ_BASE_URL` 已停用，旧值不会使网页回退到远端服务。`VITE_CITY_UPDATE_GATEWAY_URL` 仅供上传及任务状态使用。

## 原有 Express 模式（历史实现说明）

以下接口保留给维护工具，不再是网页共享线路的读取入口。

### 原有功能背景

- 全市检索为固定默认模式，不再有实验性开关、性能警告或缩放级别门槛。
- 放大到城市（缩放级别11及以上）并停留约700毫秒，检查该市共享数据。有效则直接加载；不存在、过期或不完整则显示全市检索提示。自动检查不会触发高德全市检索；网络故障会单独提示，避免误报为没有数据。
- 设置 → 通用 → 城市线路数据：导出本次城市 JSON、查看历史并下载历史 JSON。
- 共享数据开启后，先读该城市最新快照。两个自然月内、未过滤且检索流程完整的快照直接用于绘图，跳过站点分页与逐条查线。
- 当前地图来自共享快照时，已知站点优先用快照线路关系回答；路段点击不再自动进行周边补漏。
- 数据不存在、超过两个自然月或不完整时，引导用户点击检索，才发起高德查询。两个月采用北京时间日历计算并夹紧月底日期，如12月31日到平年2月28日到期。
- 所有用户都可以在缺失或过期时发起检索并提交快照，无需管理员身份。后台先签发仅限当前城市的30分钟随机更新凭据，成功保存后失效；取消或无法保存时释放。已有更新任务、刚刚失败/保存后的冷却期和仍有效的数据不会重复启动更新。
- 数据过期时，可用城市数据卡片上的刷新图标重新检索。这一步需要用户点击，并会重新请求高德。
- 网络或仓库失败不影响地图生成，保存状态显示在设置中的城市数据卡片。

这里的“检索流程完整”仅表示请求顺利结束，不代表已经核实一个城市的所有公交线路。快照固定记录 `coverage: "observed"`。本版本没有实现全网后台爬取、跨实例的高德检索任务锁或自动纠正源数据。

## 配置（没有配置时仅启用 JSON 导出，不会向 GitHub 写入）

后端环境变量：

```dotenv
CITY_DATA_ENABLED=true
CITY_DATA_GITHUB_REPO=tsfeng6/busline
CITY_DATA_GITHUB_BRANCH=busline-data
CITY_DATA_GITHUB_TOKEN=<仅在后端设置的凭据>
```

GitHub 凭据须仅授权目标仓库的 Contents 读写权限。不要添加 `VITE_` 前缀，也不要提交到仓库。后端首次写入时自动从默认分支创建 `busline-data` 分支，不向 main 推送，也不会触发现有仅监听 main 的站点部署。

网页读取需要的构建变量：

```dotenv
VITE_CITY_DATA_ENABLED=true
```

上传暂时继续配置 `VITE_CITY_UPDATE_MODE=actions` 与 `VITE_CITY_UPDATE_GATEWAY_URL`，Actions 的回调地址是 `CITY_UPDATE_GATEWAY_URL`；这些配置不参与静态线路读取。网站发布工作流可单独手动运行，不需要调用网关。

GitHub 读写凭据只用于后台维护或 Actions，不放入前端构建变量。

## 仓库中的文件

```text
city-data/v1/北京/latest.json
city-data/v1/北京/history.json
city-data/v1/北京/history/<时间戳>-<内容摘要>.json
```

`北京` 与 `北京市` 使用同一目录；其他城市按名称区分。当前只支持市级快照，地区/框选数据不会作为整市数据上传。后续可扩展行政区代码避免重名，并增加地区级快照。

JSON 只包含城市、生成时间、检索完成状态、成功取得的线路/站点、线路查询对应关系、路径和运营时间等白名单字段。排除密钥、管理员密码、聊天内容和用户自定义线路。

## 更新与历史保护

- 最新文件、历史文件和历史索引通过一次 Git tree/commit 原子提交。
- 更新分支不强制覆盖；并发冲突最多重新读取、校验和重试三次。
- 同一后端进程通过城市更新凭据限制一个城市同时只启动一个更新，凭据30分钟到期，完成后有5分钟冷却；多个后端实例依靠 Git 分支更新冲突保护，生产多实例部署需增加共享任务锁和网关限流，才能跨实例避免重复高德检索。
- 默认展示时间最新的有效上传结果，不再因为线路/站点数量下降而停留在旧版；较晚到达的旧检索结果不能覆盖时间更新的快照。
- 不完整结果仍保留 `retrievalComplete: false` 标识，不会被当作已核实的全市全集。
- 每个城市保留最近5份快照（含当前版本），索引、旧快照文件和不再引用的分片在一次原子提交中更新。Git 提交历史仍可恢复旧文件。
- 上传相同内容但采集时间更新时也更新默认版本和有效期；重复提交同一版本不会新增记录。
- 单次上传上限为1GiB，使用无损压缩分片，不改变坐标精度。
- 维护脚本 `node --import tsx scripts/retain-city-history.ts <数据分支检出目录>` 可将已有城市整理为相同规则；在独立检出目录运行并审核 Git diff 后提交。
- 当前使用线路过滤时不发布全市快照，避免将用户筛选结果覆盖共享数据。

## API 与验证

- `GET /api/city-data/:city`：最新 JSON。
- `GET /api/city-data/:city/history`：历史列表。
- `GET /api/city-data/:city/history/:id`：指定快照 JSON。
- `POST /api/city-data/:city/refresh`：取得该城市的临时更新凭据，无需登录；已有有效数据或进行中的更新返回409。
- `DELETE /api/city-data/:city/refresh`：取消本次更新，需要 `x-city-refresh-token`。
- `POST /api/city-data/:city`：提交检索快照，需要 `x-city-refresh-token`，后端检查城市绑定、凭据有效性和数据。GitHub凭据永不下发。原有管理员维护通道仍可使用后端设置的12位以上非默认密码，但不是普通访客的必要条件。

运行 `npm run test:city-data` 验证字段白名单、原子发布、历史读取、重复内容、最新版本选择与5份历史保留和并发冲突。测试使用模拟 GitHub，既不消耗高德额度，也不写入真实仓库。

公共提交仍是客户端提供的观察数据：格式、坐标、数量与版本检查不能独立证明每条线路真实，首份数据尤其如此。正式开放大规模匿名更新时应增加服务端数据源核验和网关限流；本实现不会把“用户提交”标记为已核实的全市全集。

数据存储和对其他用户分发，应使用已获相应授权的数据。本版本不改变原数据来源的授权范围。

## 分级地理线网概览

- 概览采用2至13级标准XYZ透明PNG瓦片，每级按全球墨卡托像素生成，显示时由 AMap.TileLayer 按当前视口和缩放级别请求。不会将固定512像素城市图片持续放大，也不向浏览器发送整市向量数据来画概览。
- 达到13级才自动读取当前城市完整线路，精细图层和站点同样以13级为显示阈值。数据尚未加载完成时，13级瓦片继续显示，减少切换空白。
- 构建阶段使用所有城市最新快照生成公共稀疏瓦片金字塔和 `overview.json` v3，索引声明瓦片列表，无线路的图块返回透明图片地址而不请求404。原始坐标、历史快照与精细线路不修改。
- 瓦片使用稳定XYZ文件路径，源数据提交作为缓存查询版本，避免每次上传都使已打开页面的整个旧瓦片目录失效。进入/离开概览时重新检查轻量索引。
- 构建限定25000个瓦片及900MiB静态总预算，超限停止发布并保留旧站点。全国覆盖范围取决于已有城市数据，不能等同于已覆盖全国公交。
- 普通浏览底部悬浮工具栏已移除；新手引导在设置阶段结束，不再进入工具栏按钮教程。绘制模式和时间轴的专用操作面板不受此变更影响。


### 访客自有高德配置与检索提交

有效共享数据直接读取，不要求访客配置 Key。缺少共享数据、数据过期或主动重新检索时，必须填写并启用访客自己的高德 Web端 Key 和 Security Code；二者通过独立的同源 iframe 加载检索 SDK，不修改公共地图 SDK；配置更改在下一次检索时生效。普通搜索始终使用公共配置。配置仅保存在浏览器 localStorage，并发送至高德以调用服务，不随线路快照上传到本站。

上传无需共享密钥，仍需用户明确确认。检索结果在绘制与站台整理前准备，上传弹窗通过 Portal 挂载到 document.body，避免绘制异常、缓存失败或父级样式阻断提示。过滤后的结果只在本地展示，不作为全市快照上传。

缩略线路瓦片保持原 XYZ 地理范围，以 512×512 像素绘制并使用透明度抗锯齿，在地图中仍占 256×256 逻辑像素；仅请求视野所需瓦片。参考框、范围裁剪和对应开关已移除。


### 每日附近线路与纯数据小游戏

每日首次进入地图后使用浏览器原生定位（需要用户授权），同一本地日期只自动尝试一次；拒绝或超时后不因刷新反复申请，手动定位仍可重试。位置只在页面内存中用于计算，不发送给线路服务；将浏览器 WGS84 坐标本地转换为 GCJ-02，按点到线路轨迹的最短距离查找500米以内的全部已收录线路，而非只查找附近站点。日期标记保存在 localStorage，并使用可用的浏览器 Web Locks 避免多标签页同时自动定位。

小游戏只从同源城市目录和已发布快照出题，不调用高德 PlaceSearch、LineSearch、StationSearch、DistrictSearch 或 Geocoder。目录每次打开游戏刷新，快照缓存最多两个城市；目录版本更新时清理旧缓存。省份和城市选择仅列出已发布城市，地狱模式同样指定城市但不做线路名称过滤，易中难排除专线、机场、铁路等复杂命名，仅保留数字和简单前后缀路线。原公共API每日游戏次数限制已移除，底图渲染仍使用地图 SDK。

发布时根据已有“某县/区/旗政府”站点生成县城近似中心（`source: government-stop`），没有已保存定位的县城不出题。按用户确认采用政府站点近似坐标，题目注明依据；周边3公里以外的线路实际裁剪掉，同时叠加不透明周边蒙版，复盘也使用裁剪结果，退出游戏移除蒙版。小游戏不再调用临时定位或补全线路接口。

两种站点通达度检索入口均不再自动缩放或调整中心。

### 发布构建的内存限制

全国 HD 缩略图使用每像素一个字节的覆盖率数组，发布时最多保留128张512×512瓦片（驻留栅格32 MiB）；其余未完成瓦片暂存到独立临时目录，后续城市与重叠线路继续合并最大覆盖率，输出PNG仍保持原有分辨率、抗锯齿与地理范围。临时文件在成功或失败后清理，历史快照与数据分支不变。构建日志按城市报告进度与驻留栅格占用；不再把全国各级瓦片的每个像素累积到JavaScript Map中。
