# 城市线路 JSON 与 GitHub 历史快照

## 推荐部署方式

当前推荐使用 [Worker + GitHub Actions](city-actions-deployment.md)。用户只提交城市名称，Actions 负责查询和保存，浏览器不会重复全市检索。Worker 的 D1 小表仅用于任务状态与限流，公交 JSON 和历史仍存 GitHub。

以下介绍原有 Express 接收快照模式，作为可选方案保留；其后端变量和更新凭据不适用于推荐的 Actions 模式。

## 原有 Express 模式已实现

- 全市检索为固定默认模式，不再有实验性开关、性能警告或缩放级别门槛。
- 放大到城市（缩放级别11及以上）并停留约700毫秒，检查该市共享数据。有效则直接加载；不存在、过期或不完整则显示全市检索提示。自动检查不会触发高德全市检索；网络故障会单独提示，避免误报为没有数据。
- 设置 → 通用 → 城市线路数据：导出本次城市 JSON、查看历史并下载历史 JSON。
- 共享数据开启后，先读该城市最新快照。两个自然月内、未过滤且检索流程完整的快照直接用于绘图，跳过站点分页与逐条查线。
- 当前地图来自共享快照时，已知站点优先用快照线路关系回答；路段点击不再自动进行周边补漏。
- 数据不存在、超过两个自然月或不完整时，引导用户点击检索，才发起高德查询。两个月采用北京时间日历计算并夹紧月底日期，如12月31日到平年2月28日到期。
- 所有用户都可以在缺失或过期时发起检索并提交快照，无需管理员身份。后台先签发仅限当前城市的30分钟随机更新凭据，成功保存后失效；取消或无法保存时释放。已有更新任务、刚刚失败/保存后的冷却期和仍有效的数据不会重复启动更新。
- 数据过期时，可用城市数据卡片上的刷新图标重新检索。这一步需要用户点击，并会重新请求高德。
- 网络或仓库失败不影响地图生成，保存状态显示在设置中的城市数据卡片。

这里的“检索流程完整”仅表示请求顺利结束，不代表已经核实一个城市的所有公交线路。快照固定记录 `coverage: "observed"`。本版本没有实现全网后台爬取、跨实例的高德检索任务锁或自动纠正源数据。

## 配置（没有配置时仅启用 JSON 导出，不会向 GitHub 写入）

后端环境变量：

```dotenv
CITY_DATA_ENABLED=true
CITY_DATA_GITHUB_REPO=tsfeng6/busline
CITY_DATA_GITHUB_BRANCH=busline-data
CITY_DATA_GITHUB_TOKEN=<仅在后端设置的凭据>
```

GitHub 凭据须仅授权目标仓库的 Contents 读写权限。不要添加 `VITE_` 前缀，也不要提交到仓库。后端首次写入时自动从默认分支创建 `busline-data` 分支，不向 main 推送，也不会触发现有仅监听 main 的站点部署。

前端环境变量（GitHub Actions 中作为 Variables 设置；修改后重新构建）：

```dotenv
VITE_CITY_DATA_ENABLED=true
VITE_API_BASE_URL=https://你的后端域名
VITE_CITY_DATA_READ_BASE_URL=
```

默认从后端读取。如果仓库和数据分支公开，也可设置以下只读地址，使前端直接读取 GitHub 静态文件：

```dotenv
VITE_CITY_DATA_READ_BASE_URL=https://raw.githubusercontent.com/tsfeng6/busline/busline-data/city-data/v1
```

私有仓库不要配置公开读取地址，应通过后端读取。该读取地址在浏览器中必须可访问且支持跨域；读取失败会回退实时检索。GitHub Pages 本身不能执行自动写入后端，写入仍需托管 Express 或部署兼容接口。GitHub 读写凭据和管理员密码只放后端环境，不放 Actions 的前端构建变量。

## 仓库中的文件

```text
city-data/v1/北京/latest.json
city-data/v1/北京/history.json
city-data/v1/北京/history/<时间戳>-<内容摘要>.json
```

`北京` 与 `北京市` 使用同一目录；其他城市按名称区分。当前只支持市级快照，地区/框选数据不会作为整市数据上传。后续可扩展行政区代码避免重名，并增加地区级快照。

JSON 只包含城市、生成时间、检索完成状态、成功取得的线路/站点、线路查询对应关系、路径和运营时间等白名单字段。排除密钥、管理员密码、聊天内容和用户自定义线路。

## 更新与历史保护

- 最新文件、历史文件和历史索引通过一次 Git tree/commit 原子提交。
- 更新分支不强制覆盖；并发冲突最多重新读取、校验和重试三次。
- 同一后端进程通过城市更新凭据限制一个城市同时只启动一个更新，凭据30分钟到期，完成后有5分钟冷却；多个后端实例依靠 Git 分支更新冲突保护，生产多实例部署需增加共享任务锁和网关限流，才能跨实例避免重复高德检索。
- 内容没有变化且仍在两个月有效期内时，不新增快照。超过两个月后验证内容未变，也会保存新的验证时间，避免每位访问者都重复刷新。
- 不完整的新数据不替换已有版本。
- 新结果线路方向少于旧版本的85%，或站点少于75%，不替换最新版本，仍保留历史供管理员检查。这只是异常检测，不能证明数据完整；真实线路撤销也可能需要人工处理。
- 若首次结果不完整，会保存为首份观察快照，但不作为完整的两个月共享结果跳过后续实时检索。
- 历史索引显示最近100个版本；更早的历史文件及 Git 提交仍保留。
- 单次上传最多30 MiB；超出时需后续增加地区拆分，不会截断后声称整市数据完整。
- 当前使用线路过滤时不发布全市快照，避免将用户筛选结果覆盖共享数据。

## API 与验证

- `GET /api/city-data/:city`：最新 JSON。
- `GET /api/city-data/:city/history`：历史列表。
- `GET /api/city-data/:city/history/:id`：指定快照 JSON。
- `POST /api/city-data/:city/refresh`：取得该城市的临时更新凭据，无需登录；已有有效数据或进行中的更新返回409。
- `DELETE /api/city-data/:city/refresh`：取消本次更新，需要 `x-city-refresh-token`。
- `POST /api/city-data/:city`：提交检索快照，需要 `x-city-refresh-token`，后端检查城市绑定、凭据有效性和数据。GitHub凭据永不下发。原有管理员维护通道仍可使用后端设置的12位以上非默认密码，但不是普通访客的必要条件。

运行 `npm run test:city-data` 验证字段白名单、原子发布、历史读取、重复内容、质量回退和并发冲突。测试使用模拟 GitHub，既不消耗高德额度，也不写入真实仓库。

公共提交仍是客户端提供的观察数据：格式、坐标、数量与版本检查不能独立证明每条线路真实，首份数据尤其如此。正式开放大规模匿名更新时应增加服务端数据源核验和网关限流；本实现不会把“用户提交”标记为已核实的全市全集。

数据存储和对其他用户分发，应使用已获相应授权的数据。本版本不改变原数据来源的授权范围。
