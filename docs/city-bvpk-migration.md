# BVPK1 迁移与验证报告

## 格式与发布

城市的当前入口仍是 `city-data/v1/<城市>/latest.json`。客户端根据 JSON 内容选择读取方式。

| 入口内容 | 读取方式 |
| --- | --- |
| 原有城市快照 JSON | 直接读取线路和站点 |
| `storage: "city-parts-v1"` | 按原清单读取 gzip JSON 分片 |
| `storage: "city-bvpk1"` | 按清单读取独立 BVPK1 容器并还原线路与站点 |

新版清单包含 `snapshotId`、城市头部字段和有序分片列表。每个分片记录字节数、SHA-256、线路数和站点数，文件路径由摘要确定。分片封装沿用实验格式，依次存储 5 字节的 `BVPK1` 魔数、两个小端 32 位 Brotli 块长度、元数据块及 `BVP1` 几何块。几何使用每线路独立的整数坐标差分、ZigZag 和 Varint，发布端使用 Brotli quality 9。

六位小数整数网格无法准确表达某条线路中的坐标时，该线路的完整路径随元数据压缩，几何索引为它保留一个空帧。生产解码器可读取北京和锦州的原实验包。读取带超精度轨迹的新版包时，使用本仓库的生产解码器，以恢复保留在元数据中的路径。

上传网关仍接收原有上传协议。Actions 和 Express 共用发布器，在原有白名单校验后按约 8 MiB 的原始记录预算切分，解码生成的实际包并逐字段比较。校验覆盖线路和站点顺序、运营信息、每个坐标值及坐标顺序。通过后才创建提交并以非强制分支更新发布。GitHub Pages 构建固定到单一数据提交，并检查发布分片的长度、摘要和容器头；城市缩略图与瓦片继续使用当前快照生成。

浏览器重新验证当前清单，并缓存以 SHA-256 命名的不可变分片。损坏或缺失的分片会绕过旧缓存重试。上传完成后，前端清除该城市的内存缓存，并在任务返回快照 ID 时核对网站当前清单，避免把同步前的版本当作刚发布的结果。Brotli 由同源、按需下载的 WebAssembly 解码器处理，适用于缺少原生 Brotli 流接口的浏览器。[浏览器解码器项目](https://github.com/ustclug-dev/brotli-dec-wasm)

分片可独立请求和解包，BVP1 索引支持从已解压分片中单独解码一路。当前地图、小游戏和离线检索仍通过兼容层取得整城数据，地图向 SDK 提交的是现有视野索引选出的线段。后续可在清单增加线路或视野到分片的索引，从网络层按需获取。

## 迁移与人工回滚

1. 先部署支持三种存储形式的网站和静态发布器，再使用新版发布器处理新的上传、更新或采集。保留原有城市和历史文件，按城市自然过渡。
2. 灰度后，从网页确认当前清单的 `snapshotId`、站点与线路，并核对旧城市仍可读取。发布失败时检查 Actions 日志和数据分支的当前入口。
3. 需要回滚时，由维护者在基于最新 `busline-data` 的独立检出中，选择已核实的上一个有效提交及具体城市。把该提交的 `latest.json` 与配套 `meta.json` 恢复为一次新的前向提交。检查它引用的分片在当前分支存在，必要时从选定提交补回缺失文件。原有历史文件继续保留。
4. 若损坏版本仍在公开的 `history.json` 索引中，维护者可在同一次回滚提交中从索引撤下该条目，保留该条目对应的归档文件和分片，供调查。回滚前验证变更范围并在临时输出目录试构建，通过后走正常数据部署，确认当前入口指向所选版本。避免用整次发布的 Git revert 回滚，因为那会尝试撤销新增的归档文件。

历史维护命令 `node --import tsx scripts/retain-city-history.ts <数据分支检出目录>` 现在只读校验当前入口及索引中的历史。日常发布、同步和读取均以当前入口为准。

## 实验数据复验

使用北京和锦州实验包中 Brotli 压缩的原始 JSON 作为基准。分别读取原实验容器和当前发布器生成的清单及分片，对还原对象逐字段比较。

| 城市 | 线路方向 | 轨迹点 | 原始 JSON | 新清单及分片 | 体积减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 北京 | 903 | 502,911 | 17,082,343 B | 1,448,837 B，3 片 | 91.52% |
| 锦州 | 186 | 58,412 | 1,860,535 B | 169,779 B，1 片 | 90.87% |

两市坐标逐点一致，最大偏差为 0 米。站点、运营字段和线路顺序与原数据一致。发布体积包含清单，单独计算网站首次加载的可复用 WASM 资产约 208 KB。北京从实验整包变为三片，锦州改用发布器统一的 Brotli quality 9，因此发布体积与旧实验不同。

可用原实验目录复验。

```bash
node --import tsx --test tests/cityDataCache.test.ts tests/cityPrefetcher.test.ts tests/viewportCities.test.ts
npm run lint

npm run lint:edgeone
npm run build
```
